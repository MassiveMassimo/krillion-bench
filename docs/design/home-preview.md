# Home preview design

The home page is a comparison tool. Read the root `DESIGN.md` for the approved ocean-blue aesthetic. Terms.so is the visual reference for its open hero, left-aligned headline, dark-to-bright background, and white content panels. The font, lighter weights, pill shapes, icons, content, and benchmark behavior belong to Krillion Bench.

Use one home-page heading across three lines: "General knowledge", "benchmark for LLMs", and "on Krillion.io". Make the first two lines translucent white at 45% opacity with 12px backdrop blur clipped to the letter shapes. Keep selectable HTML text and update the SVG clip after font loading and resizing. Allow wrapping on narrow screens. Keep the last line solid white. Do not add a subheading. Keep the copy factual and direct. Avoid slogans and product marketing. Label the primary action "GitHub" and put the Hugeicons GitHub mark in Fluid Button's `leadingIcon` slot. Keep its surface white. Label the secondary action "Play Krillion" and link to Krillion.io. Give the heading open vertical space. Keep the comparison itself compact. Put the saved date and shared question count above the aggregate table. Keep the exact question above its answers in daily views. Show model and thinking setting together. Align numeric points at the end and use tabular figures.

Use a comparison table on larger screens. Use labeled response rows on narrow screens. Both presentations must use the same data. Hide the inactive presentation from layout and accessibility APIs. The landing page now leads with the saved model/setting comparison when local development results are enabled. It links shared questions to their full answer histories. The public view keeps official runs pending and places synthetic answer examples in a separate panel. See [benchmark comparison research](benchmark-comparison.md) and [verification](landing-page-verification.md).

Keep provenance beside the results heading. Synthetic examples must never appear as official measurements. Show pending scores as text, without a numeric substitute. Explain that game acceptance does not independently establish factual correctness.

Use Fluid type roles and shared font weights. Keep the library's row feedback. Honor reduced motion. Use native links, visible focus, and a skip link. Limit decorative motion to the approved sinking-logo effect and CSS hero parallax. Do not add fictional ranks, unused filters, or fabricated daily dates.

Use Stack Sans Text through `next/font/google`. Use the lighter shared weights approved for this page: 300 for body text and 400 for the main heading and section headings. Its supported axis is `wght` (200–700); do not use Inter's `opsz` settings. Fluid's Inter-specific weight animation without reflow does not transfer to this font. Check wrapping when weights change.

Use the Fluid pill preset: 20px control and hover radii, 24px panel radii, and full rounding for badges. `ShapeProvider` selects the pill preset; CSS tokens keep structural panels consistent. Keep panel corners readable instead of making large panels elliptical. Use Hugeicons' free Stroke Rounded icons through `@hugeicons/react` and `@hugeicons/core-free-icons`. The app's `IconProvider` maps the roles used by Fluid components. Keep visible text labels and hide decorative icons from accessibility APIs.

Use Fluid Button for hero actions, date controls, question anchors, and the skip link. Keep anchors through `asChild`. Server Components pass Next.js `Link` as the child. `SkipLink` constructs its native anchor inside a Client Component to retain browser focus behavior. Use Fluid Badge for provenance and Fluid Accordion for independent attempt histories. Keep the installed press layers, hover feedback, and animation timings. Compose 44px minimum pointer targets at the call sites. The ocean actions use scoped foreground, background, and tint tokens; do not recreate their surfaces in page CSS.

Sources: [Fluid introduction and icon customization](https://www.fluidfunctionalism.com/docs), [Fluid shape tokens](https://www.fluidfunctionalism.com/r/shape-context.json), [Fluid typography](https://www.fluidfunctionalism.com/docs/typography), [Google Fonts metadata](https://github.com/google/fonts/blob/main/ofl/stacksanstext/METADATA.pb), and [Hugeicons React](https://github.com/hugeicons/hugeicons-react).

The ocean backdrop uses Tailwind v4's radial-gradient utility and OKLab interpolation. Use an ellipse centered at the top, with horizontal radius 160% and vertical radius 100%, to give the fade a shallow curve. Hold the darker navy start through 10%, place the bright blue crest at 78%, and leave the white end stop at its default position. Keep these classes literal so Tailwind can detect them:

```tsx
className =
  "ocean-backdrop bg-radial-[ellipse_160%_100%_at_50%_0%_in_oklab] from-gradient-start from-10% via-gradient-crest via-78% to-background";
```

The background height is independent of the full page length. At scroll position zero, the fade ends around the first comparison panel; adding more records must not stretch the gradient. The mobile backdrop has more vertical room so wrapped text stays above the light transition. Theme colors are declared in `globals.css`; the reusable design contract is `DESIGN.md`.

Hero parallax uses the component-local `ocean-parallax.module.css`. Root scroll progress from `0px` to `100vh` translates the gradient by `75vh` and the particles by `50vh`. This produces 25% and 50% apparent scroll speeds while content scrolls normally. Linear timing keeps the speed constant. Both fill modes preserve the initial and final offsets. Feature queries and reduced-motion media queries leave unsupported or motion-reduced views at normal speed. CSS drives parallax; the existing falling simulation only reads the particle translation to align its cached collision geometry. Sources: [animation-timeline](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-timeline) and [animation-range](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/animation-range).

Inside the backdrop, add a full-width 10rem navy-to-transparent gradient using `absolute inset-x-0 top-0 h-40 bg-linear-to-b/oklab from-gradient-start to-transparent`. This holds the full top edge at the dark navy stop while retaining the curved lower fade. Both backgrounds remain outside the accessibility tree and cannot intercept input.

Reference: [Terms.so](https://terms.so/). Gradient syntax: [Tailwind background-image documentation](https://tailwindcss.com/docs/background-image#setting-gradient-stop-positions). The reference's sampled desktop headline is 56px at weight 500, with a 960px content column. Its mobile headline is 33.15px at a 390px viewport. Krillion uses its own variable font and approved weights instead of copying that font or its exact metrics.

Place scoring rules below the comparison. Explain the attempt limit, verified equivalent corrections, completed misses, separate thinking entries, and ties. Keep official provider status explicit.

The home-only `OceanParticles` component uses the installed Motion library and one frame loop. It caches the comparison card's bounds and corner radius through ResizeObserver. Logos sink at 25–41 pixels per second with gentle sway. A circle against a rounded rectangle detects contact on all edges and corners. The first contact triggers a random impulse away from the surface and a few bubbles. That collision is consumed, so the logo then passes behind the opaque card. White marks continue to the gradient's white endpoint and disappear naturally. The layer extends one logo past that endpoint and cannot intercept input. Motion values update transforms and opacity without per-frame React renders.

Show 12 logos on desktop and eight on mobile, with at most 40 small bubbles. Cycle through all 22 approved company marks, limited to developers with published text-language model families. The animation has no visible control, as requested. IntersectionObserver and page visibility stop the frame loop. Reduced motion removes the decoration. Company marks are decorative and do not imply benchmark participation or endorsement.

Logo provenance and normalization are recorded in `public/company-logos/README.md`. These are local SVG assets from [Lobe Icons](https://github.com/lobehub/lobe-icons), with its MIT license retained. UI controls continue to use Hugeicons. Motion references: [motion values](https://motion.dev/docs/react-motion-value) and [reduced motion](https://motion.dev/docs/react-use-reduced-motion).
